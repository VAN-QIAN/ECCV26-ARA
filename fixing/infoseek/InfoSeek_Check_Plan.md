# InfoSeek Evidence Check
The critical issue of InfoSeek is that it is rarely grounded by fact.
The QA pair i.e., both Question and Answer are generated by the triplets in Wikidata.
However, it could be misaligned with external KB. e.g., the answer is not supported by the evidence section of Wikipedia page of the external KB. 

## CSV file update
1. Use `fixing/infoseek/infoseek_annotation_audit.py` to sync the answer to `data/raw/infoseek/infoseek_val.jsonl`. Otherwise for numerical and temporal questions(e.g., 00000023) the answer_eval is too flexible to reflect the faithfulness to obey the provided supporting evidence.
2. Use the infoseek_val_qtype.jsonl to update the question type, String, Numerical, Temporal

## Evidence Check
1. Go through the paragraphs of all sections to select potential sections as supporting evidence to update in the csv file. You can reuse section ids from a synced InfoSeek grounded CSV when available.
2. Faithfully follow the evidence if it supports to answer the question.
- For Numerical and Temporal questions, the original annotated answer could be quite unreliable due to the unalignment between Wikidata(where InfoSeek use triplets to build QA pairs) and Wikipage(which serves as external KB to support answer generation).Examples shown in slides.

## Annotation Check
1. Regular check as E-VQA
2. Be extremely strict with the Numerical and Temporal
- If single value doesn't exact match the evidence, update the annotation
- If two values, i.e. a range, try to exact match start and end point
- unit should be exactly matched(may introduce some math here e.g., from acres to square killometers)
3. Check the evaluation scripts to avoid any irresponsable answer be evaluated as correct.
